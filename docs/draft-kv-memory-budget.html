Assumptions and formulas

Window W = 2,048; block size = 16; BF16 features/KV/conv and FP32 recurrent state; target and draft use the same TP. HiCache stores cached raw tails on host. DCP, PP, quantized checkpoints, and ReplaySSM are excluded. The current unified pool does not support ReplaySSM. This comparison holds persistent-state and verify-scratch budgets equal on both sides.

One raw row R = 24,576 bytes. One raw tail = 48 MiB. Draft KV per row D = 24,576 / TP bytes. Target KV per row F = 20,480 / min(TP, 2) bytes. One recurrent slot M = 61.40625 / TP MiB.

Host raw storage is K × W × R per rank. GPU tails share append-only chunks of up to 256 rows. Each logical window can retain at most W + 510 backing rows, including two partial edges. Admission covers 3A active windows (live + two checkpoints) and at most 2A pending transfer leases, even when their intervals are disjoint.

Let F = min(C, 2AW) and N = 3 with overlap, otherwise 1. GPU raw admission reserves [5A × (W + 510) + N × max(F, 16A) + max(2W, min(F, AW))] × R. The last two terms cover capture staging and projection inputs: canonical-page repair can hold a concatenated window and its selected rows together. Prefill remapping reuses capture storage. At the defaults this is 9.743 GiB/rank, down from 18.047 GiB. The active latest-window payload is A × W × R; chunk slack and other lifetimes are included in the extra reserve.

Baseline: one materialized draft row per target row, with no recovery tails; it does not provide the new weight-update recovery contract. An existing private pool spanning a larger virtual-ID space can cost more. K is a planned simultaneous state occupancy/budget: unified sub-pool view maxima are overlapping capacities and must not be summed.

Retaining raw features avoids historical target replay for complete bundle hits, but introduces capture/copy and draft-reprojection work. A 32-request raw-storage microbenchmark retained 2.063 GiB with overlapping checkpoints, versus 4.5 GiB in the old ring-plus-snapshots layout. These curves compare admission budgets; they are not measured peak allocations.

At TP2, concurrency 32, and 2,048 input / 512 output tokens, measured median total throughput was 17.4k tokens/s with shared tails and HiCache, versus 17.2k before the storage optimization and 20.1k with the flag and HiCache off.
